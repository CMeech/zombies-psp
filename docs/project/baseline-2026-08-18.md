Rust and Bun were installed with their official installers. A new shell must expose their user bins:

```sh
export PATH="$HOME/.bun/bin:$HOME/.cargo/bin:$PATH"
```

## Setup

```sh
git submodule update --init --recursive
bun run setup
```

Both commands passed. Setup installed the pinned PocketJS dependencies and generated its checked bindings.

The intended PSP toolchain command is `bun run bootstrap`. On this host it installed the stable WASM target and pinned Rust nightly, then reported that LLVM was incomplete because `llvm-ar` was unavailable. The following pinned `cargo-psp` installation was stopped after its recursive Rust/LLVM source checkout made no observable completion progress for several minutes; the SDK phase was not reached. Install an LLVM distribution with colocated `clang` and `llvm-ar`, then rerun bootstrap.

## Verified build commands

```sh
bun run typecheck
bun run check:platforms
bun run build:ui
cargo build --release -p openstrike
target/release/openstrike --help
```

All passed. Platform checks resolved both PSP and Vita build plans. The PSP guest build produced `openstrike.js` (140,854 bytes) and `openstrike.pak` (571,408 bytes). The native release build produced an approximately 11 MiB executable. It emitted one dead-code warning for `reset_round` and Cargo's future-incompatibility notice for `block 0.1.6`.

## Runtime and packaging gates

Native interactive and headless commands:

```sh
cargo run --release -p openstrike -- --maps-dir "$OPENSTRIKE_MAPS" --auto-quit 5
cargo run --release -p openstrike -- --maps-dir "$OPENSTRIKE_MAPS" --script walk --screenshot out/walk
```

Neither was verified because this checkout correctly contains no copyrighted BSP/WAD data and `$HOME/Downloads/cs-maps-20260705-1836/maps` was absent. A direct headless attempt reached the executable and returned the expected actionable `--maps-dir`/`OPENSTRIKE_MAPS` error.

PSP commands:

```sh
bun scripts/psp.ts
bun scripts/psp.ts --package
```

The script failed before compilation with the specific missing-map error. The EBOOT is additionally blocked by the incomplete LLVM/cargo-psp/SDK bootstrap. No EBOOT success is claimed.

PPSSPP command:

```sh
bun scripts/e2e-psp.ts
```

The script reported `PPSSPPHeadless` absent at `$HOME/ppsspp-src/build/PPSSPPHeadless`. It also requires a local map set and successful capture EBOOT. No emulator or physical-hardware result is claimed.
